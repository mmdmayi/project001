# FaceInverse 0.4 实际验证结果

目标：Windows x64、Maya 2022 Python 3.7 / Maya 2024 Python 3.10。验证在同一物理电脑上的独立安装目录完成，不代表所有其他电脑实机验收。

## 可复查的通过项

- 两个干净的0.4离线安装目录分别通过47项数值测试、模型初始化和私有Python环境检查；依赖版本与0.3.1一致。0.3.1安装器已有干净联网安装记录，本次未把重复使用离线依赖称作0.4全新联网下载验证。
- 从真实说话视频生成24fps（48帧）、60fps（120帧）夹具；60fps由原素材复制采样生成，用于时间映射测试，不是原生60fps摄像机拍摄。
- 另有物理旋转夹具、确实包含270度方向矩阵的MP4夹具，以及间隔为1/60、2/60、3/60秒的56帧VFR夹具。共320帧追踪夹具均有检测结果。
- 物理转横后在追踪前反向旋转，恢复像素最大差为0；对应52系数最大差为0。方向元数据叠加手工旋转后的系数差同样为0。测试曾发现旧式rotate标签未写出方向矩阵，已换成真实display_rotation矩阵并强制检查非零元数据，未将无旋转文件当作通过。
- Maya 2022完整追踪/采样/烘焙：60fps 120帧、旋转24fps 48帧、VFR 56帧，共13,440个控制器关键帧。独立进程重新打开，所有控制器误差为0，实际Mesh有运动。VFR自动采用Maya的30000/1001时间单位，仍按真实时间戳映射。
- Maya 2024另对120帧60fps真实角色执行采样、烘焙、独立重开，7,200个关键帧值一致。
- 两宿主保存重开后的时间映射最大浮点误差约2.22e-16秒；这是时间数值一致性，不是视频表情重建误差。
- 真实Maya 2022 Qt操作：创建组、将原先不在60个动画通道中的已标定眉控制器加入组，生成61通道扩展工程；分别录制眉/眼/嘴3个样本，共54项明确通道约束。重算后改为24fps、起始1001帧的新工程，旧工程/旧baseline未变化，样本保留。保存重开后控制器和采样Mesh坐标误差均为0。
- 两版Maya均验证双向视频定位、不同Maya时间单位的秒数转换及参考显示旋转。显示旋转/区域/叠点开关调用Maya时间函数次数为0，避免显示刷新触发未记录Pose的时间评价。
- 独立Tracker实际Qt预览/追踪一段12帧横向视频，先转正再推理；改输入旋转后清除旧显示并标记失效，原结果文件不变。眼部放大和人工检查标记保存通过。
- 独立Tracker的实际启动器分别在Maya 2022与2024自带PySide2上启动通过，未初始化maya.standalone，GUI进程不导入MediaPipe；推理通过外部私有运行时执行。
- Maya“使用Tracker当前结果”按钮通过，复用12帧完全一致的追踪和参考缓存；不把新方向套在旧点上。

## 求解器保持一致

solver.py、pose_solver.py与0.3.1文件哈希完全相同；retarget.py仅增加输出时间参数/校验，不改数值目标与权重。同输入719/67/56帧三段旧真人追踪，共842帧，新旧控制器值和预测观察值逐值完全一致；旧已录制Pose项目重算结果也逐值一致。

有界线性子问题收敛不代表全链路、演员几何或最终物理分支折叠问题全局最优。遵照用户要求，没有替换已可用的数值算法。

## 参考帧识别的边界

测试覆盖弱系数最大值、单帧峰值、缺少几何支持、无低活动参考时不强行推荐嘴角拉起，以及有支持时仅标为待确认候选。没有独立人工FACS标注集，因此没有宣称真实视频分类准确率提高多少。没有实现FACEGOOD的拖点训练模型；可视化、区域检查和手工Pose标定是本版范围。
